# Synorive · 本机内容库

用户的本地资料索引在 Synorive 里。它统一了本机文件、网页存档、导出的聊天记录、
图片里的文字（OCR）、视频里的台词（语音转写），支持**中文语义检索**——
用户描述内容也能搜到，不需要记得文件名。

## 什么时候用

**该用**：
- 「我之前写过一个关于 X 的文档」「找一下上个月那个报告」
- 「那张截图里写的什么来着」「视频里讲 X 的是哪一段」
- 「我电脑里有没有关于 X 的资料」
- 用户让你基于他自己的资料做事（总结、对比、引用）

**不该用**：
- 搜公开网络信息 → 用 WebSearch
- 读一个用户明确给了路径的文件 → 直接用 Read
- 用户没有暗示要翻自己的东西

## 怎么用

### 先看状态，再搜

搜不到东西时，**先 `synorive_status`**。最常见的原因不是"搜索不好使"，
而是：① 那个目录压根没被索引 ② 缺模型导致语义检索没启用
③ 图片的 OCR / 视频的转写还在后台补跑没完成。

直接告诉用户"没搜到"而不查状态，是最容易误导人的做法。

### 查询串里可以直接写筛选

不用先问用户"你要限定类型吗"，直接把条件写进查询串：

```
type:pdf 预算              只搜 PDF
date:最近7天 会议          最近七天
date:2026-01..2026-03     区间
size:>10mb 视频            大于 10MB
in:D:\项目 需求            只在这个目录里
tag:重要 待办              带标签
-草稿 方案                 排除含"草稿"的
"精确短语"                 整段精确匹配
```

写错的指令不会报错，会被当成普通查询词——所以可以放心组合。

### 三个预设，按场景选

- `precise` —— 找确切的东西（型号、人名、函数名、错误码）
- `semantic` —— 只记得大概意思，说法可能对不上
- `recent` —— "最近那个……"
- `balanced` —— 默认，日常用这个

### 结果里的 id 是给你继续用的

`synorive_search` 返回的每条都带 id。拿它去：
- `synorive_get_content` 读全文（**比让用户复制粘贴省事得多**）
- `synorive_similar` 找相关的
- `synorive_similar` + `byImage: true` 对图片找相似画面，
  还能找出**视频里的相似镜头并给出时间点**

### 视频和图片的结果会带位置

视频/音频的结果带时间点（`[3:24]`），可以直接告诉用户"在第 3 分 24 秒"。
文档带页码。回答里带上这些，用户就不用自己翻。

## 几件要知道的事

**图片和视频是分两步索引的。** 快速通道先建索引（EXIF、画面向量、文件名），
图片里的文字（OCR）和视频里的台词（转写）在后台慢慢补。
所以刚加进去的图片，搜画面能搜到、搜里面的文字可能还搜不到。
遇到这种情况看 `synorive_status`，别断言"库里没有"。

**实体图谱只收高精度的那几类**（邮箱、链接、金额、日期、版本号、带后缀的机构名）。
人名地名默认不抽——中文的词性标注在这上面误判率太高，
宁可少给也不给一堆假的。所以图谱里没有某个人名不代表资料里没提过他。

**这是用户的私人资料。** 检索结果里可能有敏感内容。
除非用户明确要求，不要把检索到的原文大段复制到对外的产出里
（比如你正在写的、要发出去的文档）。
