# Synorive

**Локальный семантический поиск по всем вашим файлам — и веб-исследователь с проверкой фактов.**

Ищите документы, исходный код, PDF, изображения и видео **по смыслу**, а не по имени файла.
Затем обыщите открытый веб сразу несколькими движками, целенаправленно найдите опровержения
и получите сводку, где **каждая строка — дословная цитата с указанием источника**.

Работает полностью офлайн. Ваши файлы никогда не покидают компьютер.
Предоставляет **24 инструмента MCP** для Claude Code.

## Зачем ещё один поисковый инструмент?

Большинство инструментов «поиск по вашим файлам» останавливаются на совпадении ключевых слов,
а большинство «ИИ-исследователей» выдают гладкую сводку, которую вы не можете проверить.
Synorive отказывается и от того, и от другого:

- **Производительность измерена, а не заявлена.** Каждая цифра ниже получена на реальных данных —
  **включая две, которые до цели не дотянули**. Они остались в таблице вместе с причиной,
  а не были тихо убраны.
- **Ничего не отбрасывается молча.** Результаты, отсеянные как низкокачественные, попадают в ящик
  «исключённые» с указанием причины; один клик — и они вернутся.
- **Он никогда не скажет вам, что нечто ложно.** Он находит тех, кто оспаривает утверждение,
  и показывает обе стороны. Судить об истине он не умеет, а притворяться, что умеет, было бы
  самым опасным, что он мог бы сделать.

## Что работает сегодня

Этапы 1–3, 5 и 8 завершены. **Приложением действительно можно пользоваться уже сейчас.**

### Поиск по собственным файлам

- Перетащите папку, где вперемешку документы, код, картинки и видео → индексация идёт параллельно
  в фоне, интерфейс не подвисает
- Семантический поиск по документам на китайском и английском — опишите содержание, помнить
  имя файла не нужно
- Синтаксис запроса прямо в строке поиска: `type:pdf date:last7days -черновик "точная фраза"`
- Поиск текста *внутри* изображений (OCR, измеренное покрытие символов — 100 %)
- Найдите похожие изображения по одной картинке или **из какого видео взят кадр и на какой секунде**
- Найдите произнесённую реплику и перейдите сразу к 3 мин 24 с видео
- Статьи индексируются по разделам (Abstract / Method / Results); попадания помечаются как
  `стр. 2 · Background`
- Спросите у PDF **«на какие вопросы ты можешь ответить?»** и щёлкните, чтобы развернуть исходный фрагмент

### Поиск в вебе и его проверка

- Много движков параллельно (cn.bing / Baidu / 360 / Mojeek / Википедия); с собственным SearXNG
  **работают также Google и DuckDuckGo**
- Глубокое исследование **сначала читает первый круг, а потом само решает, что спрашивать дальше**,
  и ищет ещё раз
- Китайский запрос автоматически получает английский вариант, направляемый в движки с лучшим
  англоязычным охватом — первоисточники чаще всего на английском
- Целенаправленно ищет в обратную сторону: «опровергнуто / оспаривается / отозвано / спор» —
  и кладёт контраргументы прямо перед вами
- Отслеживает утверждение **до самого раннего источника**; десяток сайтов, опубликовавших одно
  и то же за два дня, помечается как всплеск перепечаток
- Процитированная статья, **которая была отозвана, помечается красным** (через OpenAlex)
- Пять академических источников объединяются по DOI, с числом цитирований и ссылками на PDF

### Использование из Claude Code

После `claude mcp add synorive` Claude Code может искать в вашей библиотеке, проверять утверждение
и сопоставлять **то, что есть у вас**, с **тем, что говорит веб** — в одном и том же ответе.

Полный технический проект и меню из 76 функций — в
[`docs/00-技术方案.md`](../00-技术方案.md). Каждая цель по производительности, критерий «считается
измеренным» и **то, что ещё не протестировано**, объявлены прямо в коде:
[`engine/synorive/metrics.py`](../../engine/synorive/metrics.py); скрипты замеров лежат в
[`engine/tests/`](../../engine/tests) (`bench_g_series` / `bench_research` / `bench_ingest_stages`).

## С чего начать

```bash
# 1. Зависимости Node (Node ≥20)
npm install

# 2. Сгенерировать подмножество шрифтов (6 МБ, в репозитории нет, нужно один раз собрать)

# 3. Сгенерировать иконки (уже в репозитории; нужно только при смене исходного изображения)
python scripts/build_icons.py

# 4. Python-окружение движка (Python ≥3.11)
py -3.13 -m venv engine/.venv
engine/.venv/Scripts/python.exe -m pip install -e engine
```

### Разработка

```bash
npm run dev              # Electron + Vite с горячей перезагрузкой; движок стартует сам
```

### Сборка

```bash
npm run build            # все рабочие пространства
npm run build:desktop    # только десктоп
npm run pack:win         # установщик Windows + portable
```

### Выпуск и автообновление

И десктоп, и Android проверяют обновления по **GitHub Releases** этого репозитория.

```bash
npm run version:check      # согласованы ли все четыре номера версии?
npm run version:set 0.1.2  # меняет все четыре разом — руками их править нельзя
npm run android:keystore   # первый раз: создать релизное хранилище ключей Android (вне репозитория)
npm run release            # собрать оба артефакта, БЕЗ загрузки
npm run release:publish    # собрать и создать GitHub Release (требуется вход в gh)
```

Есть четыре способа сломать цепочку обновления **вообще без каких-либо ошибок**.
`scripts/release.mjs` блокирует каждый:

| Чего не хватает | Что видит пользователь |
|---|---|
| `latest.yml` не загружен | Десктоп пишет **«у вас последняя версия»**, а не ошибку — обновление никогда не придёт |
| Тег не совпадает с `package.json` | Апдейтер отдаёт 404 |
| APK не загружен | Телефон видит новую версию, но не может её скачать |
| `versionCode` для Android не увеличен | Телефон пишет **«у вас последняя версия»** |

**Границы безопасности канала обновлений** — сказано прямо, а не обтекаемо:

| | Десктоп | Android |
|---|---|---|
| Транспорт | HTTPS | HTTPS, и код жёстко отвергает любой хост, кроме GitHub |
| Целостность | sha512 из `latest.yml`; при несовпадении установка отклоняется | Число байтов должно совпасть с размером ресурса, который сообщает GitHub (сервер, оборвавший связь раньше времени, тоже возвращает −1 из `read()`, поэтому без проверки длины вы получите обрезанный пакет) |
| Подлинность | ⚠️ **Подписи кода нет.** Сертификат не покупался, поэтому проверка Authenticode пропускается, а SmartScreen предупредит о неизвестном издателе | ✅ Систе́ма проверяет подпись; APK, подписанный не тем ключом, попросту не установится |

Закрыть пробел на десктопе можно ровно одним способом: купить сертификат подписи кода и указать
`publisherName` в `electron-builder.yml`.
**До тех пор не преподносите это как «безопасные обновления».**

Два известных ограничения — оба заложены в проект, а не являются багами:

- **Portable-версия не умеет обновляться сама.** Однофайловый самораспаковывающийся сборник
  запускается из временной папки и не может заменить работающую копию самого себя. Приложение прямо
  говорит об этом и даёт ссылку на страницу загрузок, а не выдаёт ошибку и не заставляет
  повторять попытки.
- **Android требует ручного подтверждения установки.** Распространение вне магазина может лишь
  вызвать системный установщик, который в первый раз просит разрешить «установку неизвестных
  приложений». Приложение проверяет это разрешение и сразу открывает нужный экран настроек.

```bash
npm run build --workspace=@aevorine/synorive-mcp

```

Затем откройте новую сессию Claude Code и спросите «я что-нибудь сохранял про X?» — поиск
запустится автоматически.

**24 инструмента:**

- **Локальная библиотека** — `search` / `ingest` / `analyze` / `get_content` / `similar` /
  `timeline` / `graph` / `status` / `questions`
- **Веб** — `web_search` / `research` / `scholar` / `read_url` / `web_engines` / `verify` /
  `unified_search`
- **Литература** — `scholar_review` (тематический обзор, только цитаты), `scholar_table` (одна
  метрика по многим статьям), `citations` (со-цитирование, чтобы найти основополагающие работы),
  `harvest` (массовая выгрузка полных текстов открытого доступа в библиотеку, по умолчанию
  вхолостую)
- **Проверка и память** — `check_numbers` (сверить каждую цифру с исходным текстом),
  `memory` (что я уже искал по этой теме?)
- **Локальные медиа** — `compare` (чем различаются два файла), `chapters` (оглавление длинного видео)

Всё, что возвращается Claude, **несёт разбивку по доверию и источник**, а описания инструментов
прямо очерчивают границы их возможностей («не может судить, истинно ли утверждение по существу»,
«дословное извлечение — не пересказ», «наличие опровержений ≠ исходное утверждение ложно»).
Без этого Claude уравнял бы контент-ферму и официальную спецификацию и пересказал бы обе
с одинаковой уверенностью.

Адрес движка определяется автоматически из `data/engine.json`: если десктопное приложение запущено,
MCP-сервер подключается к тому же движку; если нет — поднимает свой. Переопределяется через
`SYNORIVE_ENGINE_URL`.

### Как заставить работать Google и DuckDuckGo (необязательно, но настоятельно рекомендуется)

Замеры августа 2026 года: Google теперь требует JavaScript (по обычному HTTP приходит лишь страница
перенаправления), html-эндпоинт DuckDuckGo превратился в JS-заглушку, Yandex отдаёт капчу,
а **все семь публичных инстансов SearXNG вернули 429/403**. На практике остался ровно один
бесплатный путь к этим движкам: **поднять собственный SearXNG.**

```bash
node scripts/setup-searxng.mjs            # показать, что он собирается сделать (вхолостую, ничего не меняет)
node scripts/setup-searxng.mjs --apply    # действительно установить (нужен Docker)
node scripts/setup-searxng.mjs --status   # он ещё жив?
```

Движок **сам находит и включает его при холодном старте** — искать переключатель в настройках
не нужно. По замерам после установки: `google cse` дал 20 результатов сам по себе, DuckDuckGo — 10,
тогда как при прямом обращении оба возвращают ноль.

## Неочевидные проектные решения

- **Веб-поиск и облачный вывод — два переключателя, а не один.** Веб-поиск выдаёт, *о чём вы
  спрашиваете*; облачный вывод выдаёт, *что у вас уже есть*. Это разные риски, поэтому слияние их
  в единый «приватный режим» позволило бы выключить тот, что вас волновал, пока второй остаётся
  включённым.
- **Всплывающее окно с изображением из буфера обмена никогда не выходит в сеть** — даже при
  включённом веб-предпросмотре. Отправить текст — это одна фраза; отправить скриншот — это картинка,
  на которой может быть что угодно.
- **Отфильтрованные результаты сворачиваются, а не удаляются.** Одна и та же статья, найденная
  пятью движками и перепечатанная тремя сайтами, — это восемь результатов, но одна вещь. Свернуть
  её, записав «5 движков, 3 сайта», значит сохранить то самое число, которое нужно для перекрёстной
  проверки; удалить — значит его выбросить.
- **Ограничение частоты ≠ поломка.** Поисковик, отдавший капчу, — это не сломанный парсер.
  Они считаются раздельно, потому что «сбавь темп» и «этот адаптер мёртв» требуют
  противоположных действий.
- **Замеры, не достигшие цели, остаются в таблице.** Две строки выше помечены ⚠️, а не убраны.
